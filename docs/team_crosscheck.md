## 2. Overlap analysis — where the three workstreams duplicate effort

### 2.1 Scaffold-split implementations — three pipelines, two implementations

| Notebook                                                          | Implementation                                                                                                            | Ratios                  | Source        |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ----------------------- | ------------- |
| [phase3_experiments.ipynb](../notebooks/phase3_experiments.ipynb) | `tdc.single_pred.Tox(...).get_split(method="scaffold", seed=…)`                                                           | TDC default (≈70/10/20) | TDC library   |
| [unified_benchmark.ipynb](../notebooks/unified_benchmark.ipynb)   | inline custom: `MurckoScaffold.MurckoScaffoldSmiles(mol, includeChirality=False)` → group → greedy bin-pack largest-first | 70/10/20 explicit       | inline        |

Two parallel scaffold implementations means **the test sets are different molecules** even at the same seed. Cross-notebook AUROC numbers are not directly comparable. See §4.

| Hidden dim default | 128                                                                                               | passed in (no fixed default in registry)                                             |

Two unrelated GIN implementations now live in the repo — different layer counts, different defaults. Pick one before the closing report (see §4).

## 4. Conflicts / risks — non-trivial discrepancies to resolve before the closing report

1. **Two scaffold-split implementations → different test sets at the same nominal seed.**
   TDC's scaffold split (mine) and the inline Murcko-greedy split (`unified_benchmark`, `conformer_ensemble`) put different molecules in test. **AUROC numbers from `phase3_experiments.ipynb` are not directly comparable to numbers from `unified_benchmark.ipynb`** even on ClinTox seed 42. Decision needed: either (a) port `unified_benchmark`'s split into `src/` and rerun mine, or (b) port TDC's split into the teammates' notebooks. (a) is cleaner because it removes the TDC-version dependency.
2. **Two parallel GIN/GINE implementations.** [src/models.py](../src/models.py) `GIN` is 3 layers + BN + dropout; `unified_benchmark.ipynb` `GINNet` is 2 layers, no BN visible. **Pick one canonical version**, delete the other. Recommendation: keep `src/` (it's the one with executed numbers and the only one DAVIS warm-starts from), have `unified_benchmark` `import` from `src.models` instead of redefining.
3. **Featurization mismatch (141 vs 9 atom dims, 6 vs 4 bond dims) breaks weight portability.** A `models/v3/ClinTox/GIN_seed42.pt` from `unified_benchmark` cannot warm-start `dti_davis.ipynb` because the input projection has a different shape. The conformer notebook loads `GIN_seed42.json` for a 2D comparator — same problem if the convention diverges. **Standardise on one featurizer (recommend `src/featurize.py`)** before any cross-notebook checkpoint sharing.
4. **`pos_weight` convention is consistent (`n_neg / n_pos` everywhere)** — `src/training.py`, `unified_benchmark` (lines computing `pw = n_neg / n_pos`), and `conformer_ensemble` all agree. ✅ no conflict here. **But focal loss is missing across all three** (mid-term step-1 commitment).
5. **Filename collision risk on DAVIS warm-start.** [dti_davis.ipynb](../notebooks/dti_davis.ipynb) `gin_enc.load_pretrained("../models/GIN_clintox.pt")` reads from the **flat** `models/` namespace. If `unified_benchmark` is run, it writes to `models/v3/ClinTox/GIN_seed{42,123,456}.json` (a different directory and file format — JSON metadata, not `.pt`), so the existing `models/GIN_clintox.pt` is **not** physically overwritten. **However** the conceptual collision is real: which GIN ClinTox checkpoint is the "official" one to warm-start from? Recommendation: pick the best-val seed from the v3 sweep, save it as `models/GIN_clintox_v3.pt`, and update [dti_davis.ipynb](../notebooks/dti_davis.ipynb) to load that explicitly. As-is, DAVIS warm-starts from the seed=456 checkpoint (the last seed `phase3_experiments.ipynb` happens to write).
6. **Two separate v3 namespaces drifting.** Mine writes flat to `models/` and `results/`; teammates write to `models/v3/` and `results/v3/`. Closing-report tables will be ugly to assemble. Recommendation: migrate mine to `models/v3/` and `results/v3/` once the teammates' notebooks are committed (low-risk rename).
7. **`conformer_ensemble.ipynb` depends on a `unified_benchmark` artifact that doesn't exist yet.** It tries to load `models/v3/ClinTox/GIN_seed42.json` to compare SchNet's conformer-mean to the 2D-GIN baseline. Until `unified_benchmark` runs ClinTox at least once, the conformer notebook's comparison row is broken.
